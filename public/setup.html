← Open your office

Give your agents an office.

A few commands connect Codex and Claude Code. Anyone can create an office. Offices start private; you can open a public visitor link later.

1. Save your two files

On the homepage, click Get your office → Create my office. Download the recovery file and connection file. Keep both private. The recovery file is your way back in; there is no email reset.

2. Pair your computer

You need Node.js 22.18 or newer and Git. Open a terminal and run:

git clone https://github.com/michaelraim/tinyagents.git
cd tinyagents

If you already have the project, open a terminal in that folder instead.

Windows PowerShell

node bridge/setup.mjs "$env:USERPROFILE/Downloads/sidequest.config.json"
node bridge/office.mjs doctor

macOS or Linux

node bridge/setup.mjs "$HOME/Downloads/sidequest.config.json"
node bridge/office.mjs doctor

Change the file path if you saved it somewhere else. Look for Ingest credentials accepted. You do not need to run a local web server or install this project's npm dependencies just to connect.

3. Install in your coding client

Codex

codex plugin marketplace add michaelraim/tinyagents
codex plugin add sidequest-office@tinyagents

Restart Codex. Enable the plugin and review/trust its hooks in /hooks. If your Codex version has no plugin commands, update it or open this repository in the desktop app and look for Tinyagents in its plugin directory.

Claude Code

claude plugin marketplace add michaelraim/tinyagents
claude plugin install sidequest-office@tinyagents --scope user

Restart Claude Code and check /hooks. Install both if you use both; they share the same office connection.

Updating an installed observer

Version 0.4 adds repository and client identity. Update each installed plugin, then restart the coding client and review its hooks again.

Codex

codex plugin marketplace upgrade tinyagents
codex plugin add sidequest-office@tinyagents

Claude Code

claude plugin marketplace update tinyagents
claude plugin update sidequest-office@tinyagents --scope user

Your office connection file stays the same.

4. Start a task

Ask a connected agent to read a file or run a test in one of your projects. Its room and coworker should appear within a few seconds. Start another project or subagent to see the office grow.

Empty office? Run node bridge/office.mjs doctor. Check that Node is on your coding client's PATH and that its hooks are enabled and trusted. A client running inside WSL or on another machine needs pairing in that environment. This observer supports locally running Codex/Claude sessions; cloud-orchestrated Codex sessions cannot run these local hooks.

One office, both coding clients

Install both plugins and pair once. They read the same ~/.sidequest/config.json. Use that same connection file on additional computers or inside WSL. Each client keeps its own people and sessions in your office.

A project is identified by its Git origin, not its name. Codex and Claude working on the same repository appear in the same project. Subfolders, worktrees and SSH/HTTPS clones of that origin group together. Different repositories with the same name stay separate. Without a Git remote, the observer uses the Git common folder; without Git, it uses the real folder path. Only a fingerprint leaves your computer.

To group folders with different remotes, add overrides to your existing connection file. Keep its existing connection fields. Use forward slashes in folder paths:

"projects": {
  "C:/work/shop-web": {
    "projectId": "our-shop",
    "projectName": "Shop",
    "vertical": "commerce",
    "projectDescription": "A shop for unusually ambitious houseplants."
  },
  "C:/work/shop-api": {
    "projectId": "our-shop",
    "projectName": "Shop"
  }
}

Overrides also apply to subfolders. On macOS/Linux, use paths such as /Users/you/work/shop. Changing a repo's origin or upgrading an older observer can leave an old room visible as away; existing history is not migrated.

Room signs and character badges

Click a room sign or project in the left rail to open its directory. Add a brief with Edit room brief and select a vertical with Choose vertical & props. Room numbers and colors match character badges. ⌘ Codex and ✳ Claude identify the client; ★ identifies a team lead and ↳ a subagent.

Visit friends and share your office

Open Friends → Share my office, load your recovery file, set a public name and click Open visitor link. Copy that link to share a read-only view. Project names and room briefs stay hidden unless you enable them. Task text, tool details and private history are always excluded. Close the link there at any time.

Paste someone else's visitor link into Friends → Add friend. Choose Visit, or check In my world and Show my neighborhood. Up to three offices can share your café, arcade and meeting areas, with up to 24 characters per friend. Visit an office to see its full cast.

Start a coffee summit, rubber-duck debate, competitive stand-up or arcade rivalry. Characters between tasks take part. These are playful animations in your view; they do not send messages, control agents, or synchronize antics into your friend's browser. Friends and private room edits are stored in this browser. Publish again to update your public room designs.

Open, recover, or delete your office

Use Connect agents → Open office and load your recovery file to open it in another browser. Use Manage to replace all keys or permanently delete the office. After replacing keys, save the new files and pair your clients again.

Someone with only a viewer key can watch the office but cannot replace keys or delete it. Never share the recovery or connection file publicly.

If your connection drops

node bridge/office.mjs flush

This retries saved activity. For automatic retries while a terminal stays open, run node bridge/office.mjs watch; Ctrl+C stops it. The plugins also retry on each new hook.

This is a public beta. The office mirrors observed events; animations are playful interpretations. You still approve tools and answer agents in the coding client.
